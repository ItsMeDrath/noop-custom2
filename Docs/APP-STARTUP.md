# Welcome, setup and a personal Home

The app now launches through `AppLaunchView`. A first installation or an upgrade without `whoop.setup.completed.v1` opens the welcome flow. Completion is stored in this iPhone's preferences only after the local store saves successfully. Subsequent launches open the functional `RootView` on Home.

## First run

1. Welcome explains the app and its data sources.
2. Profile saves a name and optional age through the existing validated profile store.
3. Tracker setup runs the existing CoreBluetooth scanner only after Search is tapped. The list contains discovered sensors, supports connection and timeout/error messages, and permits connecting later. A Bluetooth link does not assert that heart-rate notifications are streaming.
4. Data setup opens existing Apple Health import, configured account bridge, or JSON/CSV import. All are optional; continuing without data opens an empty personal dashboard.

Bluetooth access is not requested when leaving welcome/profile screens. The previously connected peripheral identifier is saved after a successful connection. Returning to Home attempts to reconnect that identifier without automatically scanning. Device and firmware compatibility still require physical testing.

## Personal Home and existing functionality

Home uses `AppStore.selectedDay`, the selected UTC date and fresh sensor readings. Live heart rate expires after ten seconds. Missing scores are labelled NO DATA; no score is generated by setup or a Bluetooth connection. An empty day offers tracker connection, Apple Health and account import. Existing Sleep, Recovery, Strain, Nutrition and More routes are reachable through the actual navigation shell. Journal, workout recording, backups, day imports, Profile personalization and all four measurement export formats remain available. Live opens the current fullscreen camera with `reference: nil`.

The root injects the existing HealthDataModel and NutritionViewModel so their screens share the application's existing storage and settings. Account import still requires the user's configured HTTPS OAuth bridge; no fake login or cloud session is created.

Screenshot Home is now an explicit More → Explore → Screenshot layout preview destination. It never supplies normal launch or personal dashboard values. Example-week previews remain opt-in. LaunchDayData filters saved example days on app launch and preserves all non-example measurements. Profile, journal, activities and nutrition are not cleared during this migration.
